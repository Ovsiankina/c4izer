# Structurizr 6.2.4 reference outputs (exporters row, SRS 4.7 P3-406..P3-421)

Generated by `generate.sh` in this folder from Structurizr 6.2.4:
`example/`, `deployment/`, `dynamic/` and `styles/` on 2026-11-18 from
the installed CLI (v2026.10.26, `~/.local/share/structurizr/structurizr.war`);
`edge/` in fix round 1 from the source build of `structurizr-application`
(`~/.local/src/structurizr`, the same `structurizr-export` 6.2.4, which
reproduces the first four folders byte for byte). Tests compare c4rizer's
output with these files; they never run Java or touch the network.

| folder | source fixture |

| `styles/` | `tests/data/styles/all_styles.dsl` |

Each folder's `structurizr.dsl` is the file Structurizr was given: the
fixture with its c4rizer-only view lines removed (`subtitle`,
`technology`, `bus`, `labelWidth`, `maxCrossings`, `at`, `size`, `hide`,
`focus`, `via`, `line`), since Structurizr refuses them. They are layout
and drawing aids and change no text export (see "c4rizer-only lines"
at the end). For `styles/`, the `theme`/`themes` lines are removed too: the
theme export holds the workspace's own styles only, and `theme default`
would make Structurizr fetch a URL.

## Differs (accepted)

The only byte differences c4rizer's text exports may have from these
files:

- **Final newline (P3-403).** Structurizr writes no newline after the
  last line (`@enduml`, `}`, `end`, a JSON's closing brace, an Ilograph
  file ending in a relation); c4rizer ends every text with exactly one.
  Tests compare against the reference with that newline added.
- **The duplicated `S.B` rectangle of view `comp` (P3-406)** may be left
  out; c4rizer currently writes it, as Structurizr does, so this
  difference is allowed but not taken.
- **`json/`** is compared semantically (P3-413, P3-416), never byte for
  byte.

## c4rizer-only lines

`subtitle`, `technology`, `bus`, `labelWidth`, `maxCrossings` (view
options), `at`, `size`, `via`, `line` (layout), `hide` and `focus`
(drawing) change how c4rizer draws a view, never which elements and
relationships it holds. No text format reads them, so removing them for
Structurizr changes no reference output; `dot --positions` (P3-411) and
`json` (P3-414) carry positions from c4rizer's own scene.
